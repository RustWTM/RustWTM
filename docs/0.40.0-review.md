# RustWTM 0.40.0 release scope and validation

## Scope

An OLED theme, and fixes to the CPU and container alerts, the global
show / hide shortcut and a start in the tray. Protocol 20 is unchanged;
a 0.39.2 service and a 0.40.0 window work together.

- **OLED theme.** Settings and the first-run setup offer OLED next to
  System, Light and Dark (contributed in #6). It is egui's dark mode with
  true-black panels and windows, near-black controls with visible
  borders, and no flyout shadows; the resource colors and the brand
  accent are unchanged. The choice is kept under its own key, so an
  earlier RustWTM opened afterwards shows the Dark theme.

- **CPU alert count.** The time a high load lasted, and the calm time
  before an alert closes by itself, carried over a break in monitoring,
  a switch between local and service sampling, and a new service
  session. Each now restarts the count. A sample the service returns
  again from its cache keeps the time it was measured and is not counted
  twice, and a stricter threshold restarts the count.
- **CPU alert clicks.** Close, snooze and hold carry the start time of
  the alert they were made on. A click that arrives after that alert
  closed by itself no longer closes or holds the next one; a snooze for
  the alert that just closed still keeps RustWTM quiet.
- **Container alerts.** A container missing from a partial Docker
  listing, container alerts turned off and on, and a switch to another
  Docker endpoint with the same context name each restart the count.
  A changed CPU or memory limit restarts only the count for that
  resource.
- **Show / hide shortcut.** A minimized window counted as shown, so the
  shortcut hid it. It now restores it, and releases the window from the
  top of the stack unless Always on top is on. The shortcut thread waits
  for its registration to be acknowledged before it reads messages, and
  ignores a key press that arrives while RustWTM closes.
- **Start in the tray.** A `--background` start hid the window for three
  frames, which could hide a window that a second start had just
  opened. It now hides the window once, and only if it is not already
  shown.

## Verification

`cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`,
`cargo doc` with warnings denied and the workspace tests pass on the
developer host from a clean checkout (1293 passed, 23 ignored).
`scripts/ci/verify-release.ps1 -Tag v0.40.0` checks the published
assets. CI adds 0.39.2 as an upgrade baseline, with the SHA-256 of its
published MSI.

A probe built on eframe 0.37 with the Glow renderer, as RustWTM uses,
started hidden with the new start-in-tray handling, stayed hidden, and
showed its window when asked from outside, three times out of three.

Test changes since 0.39.2:

- `wtm-gui` theme: `oled_theme_uses_true_black_surfaces`.

- `wtm-gui` alert watch: a monitoring break restarts recovery
  (`observation_window_restarts_recovery_after_a_monitoring_gap`); a
  threshold change restarts the overload count
  (`observation_window_restarts_overload_when_the_threshold_changes`).
- `wtm-gui` backend: `cpu_sample_continuity_preserves_cached_measurement_during_clock_adjustment`,
  `cpu_sample_continuity_restarts_after_gaps_and_source_changes`,
  `cpu_sample_replay_does_not_resume_the_overload_streak` and
  `cpu_alert_commands_do_not_mutate_a_replacement_alert`.
- `wtm-gui` container alerts:
  `observation_gap_for_an_omitted_container_restarts_its_streak`,
  `observation_gap_while_alerts_are_off_needs_no_docker_poll`,
  `observation_limits_restart_only_the_changed_resource` and
  `observation_endpoint_changes_even_if_the_context_label_matches`.
- `wtm-gui` shortcut: `shortcut_restores_a_minimized_window` and
  `shortcut_restores_without_pinning_when_always_on_top_is_off`.
- `wtm-gui` start: `background_start_hides_only_once_and_preserves_the_first_reopen`;
  `background_without_a_tray_reveals_the_window` replaces the test of the
  removed frame counter.
- `wtm-sys` shortcut thread:
  `registration_lifecycle_discards_a_key_delivered_after_shutdown` and
  `registration_lifecycle_does_not_read_messages_after_timeout`.
- Test helpers: `kill_tree_kills_descendants` waits up to 10 seconds for
  the killed processes to go, and the service tests retry a start that
  antivirus refused, or that failed with a side-by-side configuration
  error, for up to 30 seconds.

Not covered: the real RustWTM window with a real global shortcut and a
real Docker endpoint; the tests use seams for the window calls and the
Docker reports.
